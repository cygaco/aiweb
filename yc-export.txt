❯ # YC Pizza Concierge Sprint Plan for Claude: Real Menu Discovery + Pre-Order  
  Delivery Compatibility                                                        
                                                                                
  ## Project Brief                                                              
                                                                                
  I am applying to Y Combinator.                                                
                                                                                
  In this session, we will fix two major compatibility problems in the pizza    
  concierge bot:                                                                
                                                                                
  1. Restaurant menus and pricing appear to be templated or generic instead of  
  representing the actual menu for the selected restaurant.                     
  2. Delivery compatibility currently has provider-specific handling for        
  Domino’s, but for other restaurants the system often chooses not to guess and 
   stops short of resolving delivery compatibility.                             
                                                                                
  Both problems block the same core product promise:                            
                                                                                
  > The concierge should determine whether a restaurant is compatible with the  
  user’s order before attempting the order.                                     
                                                                                
  The previous compatibility work focused on answering:                         
                                                                                
  1. Does this restaurant deliver?                                              
  2. If it delivers, does it deliver to the user’s location?                    
  3. Does it have what the user wants?                                          
  4. Should the concierge confirm compatibility before making a phone call or   
  placing an order?                                                             
                                                                                
  However, our solutions primarily centered on confirmation during call         
  ordering. This sprint focuses on making those checks before the order is      
  attempted.                                                                    
                                                                                
  The larger vision is the discovery, compatibility, and trust layer for the    
  agentic economy. For now, build a tight, demoable wedge: the pizza concierge  
  should not pretend every restaurant has the same menu, and it should not      
  attempt an order without resolving delivery compatibility.                    
                                                                                
  ---                                                                           
                                                                                
  ## Core Problems                                                              
                                                                                
  ### Problem 1: Templated Menus                                                
                                                                                
  The current system appears to use templated menus or generic menu             
  assumptions.                                                                  
                                                                                
  This causes dangerous false positives:                                        
                                                                                
  - The concierge may claim a restaurant has a pizza it does not have.          
  - The concierge may attempt to order an unavailable item.                     
  - The concierge may make unnecessary phone calls.                             
  - The concierge may damage user trust by acting confident without evidence.   
  - The system cannot properly decide whether a phone call or order attempt is  
  justified.                                                                    
                                                                                
  The system must distinguish between:                                          
                                                                                
  - A real menu item found on a restaurant-specific source.                     
  - A likely/common pizza inferred from cuisine type.                           
  - A generic template item.                                                    
  - A cached menu item.                                                         
  - A stale cached menu item.                                                   
  - An unknown item that requires confirmation.                                 
                                                                                
  Generic templates may be used only as fallback language or test fixtures.     
  They must not be treated as restaurant-specific truth.                        
                                                                                
  ### Problem 2: Delivery Compatibility Is Too Narrow                           
                                                                                
  The current implementation checks delivery compatibility for                  
  ──── (2104 lines hidden) ──────────────────────────────────────────────────── 
  de at least six examples:                                                     
                                                                                
  ### Demo 1: Generic Template Rejected                                         
                                                                                
  User asks for pepperoni pizza.                                                
                                                                                
  System finds a candidate restaurant.                                          
                                                                                
  The only menu data is generic/template data.                                  
                                                                                
  Old behavior would treat the item as available.                               
                                                                                
  New behavior marks the menu as generic and does not confirm availability.     
                                                                                
  ### Demo 2: Real Menu Confirms Item                                           
                                                                                
  User asks for pepperoni pizza.                                                
                                                                                
  System finds restaurant-specific menu evidence.                               
                                                                                
  The requested item appears on the menu.                                       
                                                                                
  System marks item as available and proceeds through compatibility checks.     
                                                                                
  ### Demo 3: Real Menu Shows Substitute                                        
                                                                                
  User asks for supreme pizza.                                                  
                                                                                
  System finds restaurant-specific menu evidence.                               
                                                                                
  The exact item is missing, but a similar item is available.                   
                                                                                
  System asks user whether the substitute is acceptable before calling or       
  ordering.                                                                     
                                                                                
  ### Demo 4: Unknown Menu Leads to Focused Call                                
                                                                                
  User asks for a common pizza from a strong candidate restaurant.              
                                                                                
  No reliable menu evidence exists.                                             
                                                                                
  Delivery and location compatibility are otherwise strong.                     
                                                                                
  System allows a focused phone call with a clear objective:                    
                                                                                
  > Confirm whether they can make the requested pizza and deliver it to the     
  user.                                                                         
                                                                                
  ### Demo 5: Non-Domino’s Delivery Checked Before Order                        
                                                                                
  User asks for delivery from a non-Domino’s pizza restaurant.                  
                                                                                
  Old behavior would stop at unknown or fail to check properly.                 
                                                                                
  New behavior checks delivery evidence from available sources.                 
                                                                                
  System either confirms delivery, asks for missing address info, searches for  
  another restaurant, or allows a focused confirmation call.                    
                                                                                
  ### Demo 6: Restaurant Delivers But Not to User                               
                                                                                
  User asks for pizza delivery.                                                 
                                                                                
  System finds a restaurant that appears to deliver.                            
                                                                                
  System checks coverage and determines the user is out of range or likely out  
  of range.                                                                     
                                                                                
  System does not place the order.                                              
                                                                                
  System explains the blocker and searches for another candidate.

● Session print — Key moments YC will care about (HIGH confidence)

  This session shipped a real-evidence enrichment layer for a pizza-concierge
  agent: the bot now fetches restaurant websites and parses real menus before
  calling, instead of treating Google Places' generic 3-item template as
  confirmation. Three real demo failures from a prior live test became one
  structural fix. Sprint went from problem to merged + pushed in one sitting.
  Below are the artifacts that map to YC's 2026 RFS signals (agentic action,
  AI-native architecture, real-world traction, operational rigor, workflow
  depth).

  The failures that drove the sprint were observed, not hypothetical

  - User pasted a real Claude Desktop transcript at session start: "Did we check
   if they have the item? — Honest answer: no, not directly." That conversation
  is what the work is responding to.
  - Three failures, one cause: agent committed to an external action (a phone
  call) without checking compatibility first. Documented in
  yc-export-menu-delivery.md §"Three Real Demo Failures."

  AI-native architecture, not a wrapper

  - The compatibility gate IS the product surface. src/lib/compatibility.ts runs
   three checks (delivery / coverage / item) and gates start_pizza_order (MCP) +
   proposed_cart (A2A). It blocks the Bland call when verdict is no_go. AI is
  architecturally central — this isn't a chat UI with a model behind it.
  - The new module src/lib/menu-discovery.ts is the evidence layer: website
  fetch + Claude Haiku extraction → real menu items + delivery cues, cached 24h,
   fail-open at every error path. AbortController-enforced timeouts (3s fetch,
  4s total). See commit c41d973 (foundation) + 5d88b6c (gauntlet hardening).

  Evidence-vs-inference is the product distinction

  - Pre-sprint: places_generic_menu matches returned likely_available
  (confidence 0.6). False confidence.
  - Post-sprint: generic-template matches return unknown (template is not
  evidence). Real-menu matches via menuSource: "restaurant_website" return
  available (confidence 0.85, source menu_match). See
  src/lib/compatibility.ts:269-284, tests #21+#22 in
  tests/compatibility.test.ts.
  - The bot now distinguishes "I have evidence" from "I'm inferring" — and acts
  only on evidence.

  Two correctness fixes that automated tests would not have caught

  - User-flagged: "Domino's HAS a website." The implicit no-website skip wasn't
  enough — a future commit populating dominos.com on the connector would
  silently let enrichment overwrite truthful provider-adapter data with a
  marketing page. Fix: explicit dominos_* id-prefix early-return in
  enrichEvidence. Test #9 in tests/menu-discovery.test.ts verifies
  skip-with-website-set. Commit 2001634.
  - menuSource ambiguity bug caught in pre-fix gauntlet review: enrichment would
   run, cache would be written, but checkItemAvailability would still hit the
  generic-template branch because enriched restaurants retain the places_ id
  prefix. Without this fix, the entire enrichment layer would have shipped
  looking like it worked but doing nothing user-visible. Fix:
  Restaurant.menuSource field, set by applyEnrichment, checked by
  checkItemAvailability. Commit 2001634.

  Cross-provider gauntlet caught 4 HIGH issues tests didn't

  - 3-gate gauntlet (reviewer + compliance + qa via OpenAI gpt-5.5 at xhigh
  effort) ran against feat/menu-discovery @ 2001634 via
